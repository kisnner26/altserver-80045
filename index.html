The failure

Issue #1828
What you see

Two errors.
One cause.

Installing AltStore from AltServer on macOS 27 failed at the very first sign-in request, before Apple ever looked at the password. Sideloadly, iloader, SideStore and xtool failed the same way, so the tool is not the problem.

What changed

Timeline
Two blocks, not one

Apple checks
that they agree.

01

Oct 5 · it works

AltServer signs in on macOS 27 with anisette data generated locally by AnisetteKit, which emulates Android's CoreADI.

02

Oct 12 · -80045

The anisette describes an Android device but the X-MMe-Client-Info header says Mac. Apple starts rejecting the mismatch. Declaring a Pixel client fixes it for a few hours.

03

Oct 14 · HTTP 503

From about 20:50 UTC, any Android client info gets a 503 Service Temporarily Unavailable HTML page, which AltServer tries to read as a property list.

The rule

The anisette and the client info must describe the same device.

A crash that wasn't the bug

Xcode 27
UML components · build chain

The framework
that was empty.

Porting the fix meant building AltServer with Xcode 27, and the first build that reached Apple crashed on its own. The faulting call was alt_ccsrp_gp_rfc5054_2048, a symbol AltSign binds through the flat namespace. It was undefined in every framework.

$ nm -arch arm64 AltSign.framework/Versions/A/AltSign | grep rfc5054
                 U _alt_ccsrp_gp_rfc5054_2048

$ clang -dynamiclib -arch arm64 -Wl,-force_load,libcorecrypto_static.a \
    -undefined dynamic_lookup -o AltSign-Dynamic.framework/Versions/A/AltSign-Dynamic

Rebuilding that one dylib from the static library removed the crash. It is a build issue and is deliberately not part of the pull request.
