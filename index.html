Apple closedthe door.Twice.

On October 12, AltServer stopped signing in to Apple on macOS 27. A fix worked for one day, then Apple blocked it too. This is how the failure was traced, what finally passes, and what has been proposed to AltStore.

01 / the failurescroll to exploreissue #1828
01 / the failure

Two errors, one cause.

Installing AltStore from AltServer on macOS 27 failed at the very first sign-in request, before Apple ever looked at the password. Hundreds of people hit it in the same few days (altstoreio/AltStore#1828), and the tool that signs in is not the problem: Sideloadly, iloader, SideStore and xtool failed the same way.

Two days later the message changed. The sign-in request was now answered with an HTML page, and AltServer tried to read it as a property list:

The second error looks unrelated. It is the same door, closed a second time.

02 / the timeline

What Apple changed.

On macOS 27, AltServer generates its anisette data locally with AnisetteKit, which emulates Android's CoreADI. The anisette headers describe a device, and the X-MMe-Client-Info header describes the client. Apple started checking that the two agree.

The first block was reported by the anisette server maintainers (anisette-v3-server#61). The community answered it by declaring a Pixel client instead of a Mac, which worked for a few hours. The second block arrived when Apple's edge began answering every Android client info with 503 Service Temporarily Unavailable.

03 / probing the edge

Ask the server, carefully.

To see what Apple accepts, I sent credential-less requests to gsa.apple.com/grandslam/GsService2 with only the client info changed and an empty property-list body. These probes say how the edge routes a request, not whether a login would succeed. They produced the picture below on October 15 (measured between 03:40 and 04:30 UTC).

X-MMe-Client-InfoResponseReading

<MacBookPro…> <macOS;27.2;…> akd404 / 429reaches the service (and my IP was rate-limited by then)

The only recipe confirmed working after the 503 was the one iloader 2.3.8 and isideload 0.4.6 shipped: anisette data generated by Windows' ADI (iTunes) on an anisette v3 server, with the client info and user agent that server reports, used for provisioning, for GsService2 and for 2FA. A Mac client info is used only to look up the URL bag.

04 / a crash that wasn't the bug

The framework that was empty.

Porting the fix meant building AltServer with Xcode 27, and the first build that reached Apple crashed on its own: EXC_BAD_ACCESS at address 0x0, a call through a null function pointer from inside AltSign, right at the start of the SRP handshake.

The faulting call was alt_ccsrp_gp_rfc5054_2048, a symbol AltSign binds lazily through the flat namespace. nm showed it undefined in every framework. It lived in libcorecrypto_static.a, which was built but linked into nothing: with Xcode 27 the AltSign-Dynamic package product is generated as an empty framework, and in older toolchains it carried all that code.

$ nm -arch arm64 AltSign.framework/Versions/A/AltSign | grep rfc5054
                 U _alt_ccsrp_gp_rfc5054_2048

$ clang -dynamiclib -arch arm64 -Wl,-force_load,libcorecrypto_static.a \
    -undefined dynamic_lookup -o AltSign-Dynamic.framework/Versions/A/AltSign-Dynamic

Rebuilding that one dylib from the static library removed the crash. It is a build issue and is deliberately not part of the pull request.

05 / the fix

Sign in as who you are.

On macOS 27, AltServer now gets its anisette data from a Windows anisette v3 server instead of AnisetteKit, and signs in with exactly the identity that server reports:

BeforeAfter
AnisetteAndroid CoreADI, local (AnisetteKit)Windows ADI, anisette v3 server
User-AgentAuthKit/1 (Macintosh…) (com.apple.dt.Xcode/26.0)the server's user_agent
Extra headersnoneAccept, X-Xcode-Version, X-Apple-App-Info, Connection: close
cpd14 fields, booleans9 fields, strings
HTTP errorsplist parse error 3840readable HTTP status

Your Apple ID password and 2FA code go straight to Apple. The anisette server only sees the anisette device identity, as with AltStore's existing remote anisette mode. The change is split into three commits in AltStore and three in AltSign, builds on the 2FA fix from AltSign#59 and reuses the fetcher from #1806.

06 / evidence

It signs in. It installs.

Tested on macOS 27.2 with a free Apple ID with 2FA (the code generated on a trusted device, because the SMS option currently fails). Installing AltStore from the downloaded build worked on an iPad Pro and on an iPhone 15 Pro Max; refreshing AltStore from the app worked too.

07 / limits

What this doesn't do.

It is not universal. Some accounts still get -80045 with the Windows identity (nab138/iloader#928), apparently depending on the account or the network. It depends on a third-party server. SMS 2FA fails on Apple's side. Refreshing other sideloaded apps was not tested. And Apple can change the rules again: the first fix lasted less than a day.

For people who cannot wait for a merge there is an unofficial, unsigned build, clearly marked temporary, with checksums and the patches it was built from. Read its notes first.
