Timeline

01

Oct 5 · it works

AltServer signs in with anisette data generated locally, emulating Android's CoreADI.

02

Oct 12 · -80045

The anisette says Android but the client info header says Mac. Apple starts rejecting the mismatch.

03

Oct 14 · HTTP 503

From about 20:50 UTC any Android client info gets a 503 HTML page.

The rule

The anisette and the client info must describe the same device.

A crash that wasn't the bug05 / 09 · XCODE 27
Build chain

The framework
that was empty.

Building AltServer with Xcode 27, the first run that reached Apple crashed on its own. A symbol AltSign binds at runtime was undefined in every framework.

$ nm -arch arm64 AltSign.framework/.../AltSign \
  | grep rfc5054
        U _alt_ccsrp_gp_rfc5054_2048

Rebuilding one dylib from libcorecrypto_static.a removed the crash. A build issue, deliberately not part of the pull request.

Limits08 / 09 · READ BEFORE YOU RELY ON IT
What this doesn't do

Not for
everyone.

01 / 03 · Accounts

Some accounts still get -80045 with the Windows identity, apparently depending on the account or the network.

02 / 03 · Third party

It depends on a community anisette server. SMS 2FA fails on Apple's side: use a code from a trusted device.

03 / 03 · Untested

Refreshing other sideloaded apps: nobody has confirmed it yet. And Apple can change the rules again.
